The profile uses the active record's sources rather than appending copper refs.

Hydrogen 1s point sampling uses isotropic directions and a radial density
proportional to r² exp(-2r/a). The sum of three exponential variates gives this
shape. The display truncates the tail at seven exponential scales and applies
illustrative size/opacity. It is not a physical-size or isotope-shift calculation.
Other atoms retain their existing qualitative cloud shapes. A one-shell atom
uses one conceptual wave cycle. One shared canvas/engine handles both elements.

the symbol to completedExplorerSymbols. The registry derives routes/buttons
without a new per-element UI branch. Do not enable unfinished harness fixtures.

Entry and data flow
Open tests/atom-engine-test.html with file://. It includes the same classic
deferred scripts and UI shell as index.html plus development-data.js and
test-harness.js. No fetch, modules, server, installation, or network is used.
The harness HTML mirrors the student shell; keep its shared markup in sync
when changing control IDs. Only the harness loads non-copper full electron/isotope records.

A future periodic table calls:
Copper.app.loadAtom({element, isotope, ion: {charge: 0}, model: 'bohr',
                    level: 'high'})
Models: bohr, wave, quantum. Levels: elementary, middle, high.
For a nonzero charge, supply electronStructure explicitly.
The result is {ok:true, atom, tier} or {ok:false, error}. Validation failure
retains the current atom. Return to Copper in the harness reloads its verified
default. Phase 5 uses a shared periodic-table home page; hydrogen and copper have student-facing explorers.
The existing Copper namespace is a compatibility name, not an engine constraint.

Adding scientific records
Register elements in a frozen catalog with atomicNumber, name, symbol,
neutralShells, neutralSubshells, neutralConfiguration, defaultIsotope and
availableIsotopes. Add fullConfiguration, neutralElectronCount, category,
period, group (null is allowed), block, descriptions by level, classroom notes,
and warnings as appropriate. Descriptions may be omitted: generic particle and
count descriptions are used. Do not copy copper conduction text into elements.
Register an isotope by ID with matching atomicNumber, integer massNumber and
boolean stable status in C.isotopes (or the development catalog). The default
isotope must be registered and belong to the same element. Document sources
locally. Optional isotope-specific lifetime/use/abundance content must be
verified independently; the current expanded isotope card is copper content.
Development elements use counts and stability without borrowing that card.

Configurations and validation
neutralSubshells is an explicit array, e.g.
{id:'2p', n:2, l:'p', occupancy:2}. IDs must be unique and agree with n and l.
Allowed l values are s/p/d/f with capacities 2/6/10/14 and l < n. Shell
populations are indexed by n-1; their sum must equal Z-charge, each shell is
bounded by 2*n*n, and each shell must equal its subshell sum. Nonzero electron
counts require occupied-subshell data at the engine entry point. Text full
configurations are formatted from those records, not parsed to guess filling.
The five test shell totals are independently asserted in qa/phase45.cjs.
Ion electronStructure supplies shells, subshells, configuration and valence.
Isotope changes use withIsotope and retain the ion structure unchanged.
Scientific records are deep-frozen; geometry and temporary view state are separate.

Valence metadata
valence.shells identifies outer shells for representative markers. Optional
importantSubshells identifies occupied states relevant to chemistry; studentNote
explains the distinction. Copper lists 3d/4s; uranium lists 5f/6d/7s. This is
metadata, not a universal rule for counting bonding electrons. Multiple outer
electron markers are retained. Selecting a category chooses one representative.

Rendering and complexity
engine-config.js is the central tuning point. Mass >150 or >12 occupied
subshells selects Heavy; otherwise Z>10 or mass>30 selects Medium; else Light.
Budgets: base cloud points 2400/3600/4200, wave segments 140/120/72 per shell,
DPR caps 2/2/1.5; heavy electron size multiplier .78 and flat nucleon disks.
Overview uses up to four layers: a 700-sample grouped core and important outer
regions. The outer-region set comes from the record. Shapes share sprite
resources. Explore caches only one 1200-point detailed representative at a time.
Sustained slow draws reduce background sampling but retain selected detail.
Bohr includes every electron. Waves represent occupied levels, not particles.
Orbit radius and framing derive from the shell count (tested 1 through 7).
Nucleus placement uses a compact set of rotated, perturbed packing sites with
exact balanced proton/neutron allocation. No nuclear energy calculation is made.

Ownership and recovery
loadAtom validates and constructs the replacement before disposing old atomic
renderers. It returns from a nucleon first, clears selection, rebuilds options,
and resets framing for the new element. It preserves pause and explanation
level unless a level is supplied. Model caches are bounded to three. dispose
clears old particles, hit arrays, clouds, sprites and focused/grouped clouds.
setIsotope rebuilds only the nucleus and shares existing electron objects.
A detail-generation failure falls back to Overview and displays a message.
Invalid science is rejected rather than invented. Basic low-level createAtom
retains compatibility with older arithmetic-only fixtures; loadAtom requires
complete display records and status.

Limitations and next phase
Overview is qualitative grouped density, not an exact many-electron solution.
Explore shows one orientation, not every magnetic orbital simultaneously.
Radial nodes/energies are not calculated. Electron/gluon motions and nuclear
positions are educational representations. Test records are not finished
classroom content. The engine interface is ready for periodic-table integration
with validated records; expanding to all 118 requires verified records, isotope
content, age-level writing and further visual/device tests.
